# Что должна вызывать форма загрузки (контракт для фронта)

Описание для того, кто собирает форму загрузки (`app/components/UploadPrototype.tsx`) поверх бэкенда
из ветки `claude/upbeat-hugle-740cd1` (коммит `de76c9a`). Вид и вёрстка формы целиком за фронтом; бэкенд требует
только то, что описано ниже. Рабочий пример (старая вёрстка + эти вызовы):
`git show de76c9a:app/components/UploadPrototype.tsx`.

## 1. Что страница передаёт форме

`app/upload/page.tsx` (серверная страница) проверяет вход и отдаёт форме данные текущего пользователя:

| Свойство | Тип | Откуда |
| --- | --- | --- |
| `rolls` | `{ id: number; title: string; year: number; month: number }[]` | `getMyRollViews(user.id)`. Плёнки пользователя, в которые можно добавить кадры |
| `cameras` | `Camera[]` (`{ id, name }`) | `getMyCameras(user.id)`. Может быть пустым у нового пользователя |
| `films` | `Film[]` | `getMyFilms(user.id)`: справочник `FILMS` плюс свои плёнки пользователя (их id вида `u-xxxxxxxx`) |

Не вошедшего страница отправляет на вход (`redirect`), форма его не видит. Из клиентских компонентов не
импортируйте `@/lib/db`: данные приходят только пропсами, а изменения идут серверными действиями ниже.

## 2. Порядок работы формы

1. Пользователь выбирает файлы (или папку), форма сортирует их по имени с учётом чисел (`localeCompare(..., { numeric: true })`).
2. Если камер нет, форма показывает обычное текстовое поле; камеру нужно создать до старта (п. 3, `createCameraAction`).
3. Старт: `startUploadAction(...)` создаёт плёнку (или берёт существующую) и резервирует номера кадров.
4. Для каждого файла отправляется `POST /api/rolls/<rollId>/frames` с номером `idx = firstIdx + позиция в отсортированном списке`.
5. Одновременно не больше 3 запросов (так задумано в форме; сервер ограничения не требует).
6. После успеха всех кадров вызвать `router.refresh()`, чтобы обновились списки плёнок, шапка и лента.

## 3. Серверные действия (`app/upload/actions.ts`)

```ts
createFilmAction(name: string, iso: number | null): Promise<Film | null>
createCameraAction(name: string): Promise<Camera | null>
startUploadAction(input: StartUploadInput): Promise<StartUploadResult>

interface StartUploadInput {
  rollId: number | null;        // номер существующей плёнки; null = создать новую из roll
  roll: {                       // обязателен при rollId = null, иначе null
    filmId: string; format: "35" | "120"; iso: number | null;
    cameraId: string;           // id камеры из cameras (или только что созданной)
    month: number; year: number; description: string;
  } | null;
  count: number;                // сколько кадров будет отправлено (1..2000)
  totalBytes: number;           // общий размер файлов, для проверки лимита места
}
type StartUploadResult =
  | { ok: true; rollId: number; firstIdx: number }
  | { ok: false; error: string };   // error: готовый русский текст для показа пользователю
```

Что проверяет сервер: пользователь вошёл; `filmId` есть среди плёнок пользователя; `format` 35 или 120; месяц 1–12,
год 1900–2200; ISO пусто или 1–100000; описание до 5000 знаков; камера принадлежит пользователю; хватает места в архиве.
Новая плёнка **всегда создаётся с доступом «только я»**: передать другой доступ нельзя. Форма может написать
об этом пользователю («Доступ: только вы. Изменить можно в настройках папки.»).

`createFilmAction` / `createCameraAction` возвращают `null`, если не вошли или название пустое (обрезается до 80 знаков).
Список `films` и `cameras` после создания форма дополняет локально; после `router.refresh()` сервер пришлёт обновлённые
списки, поэтому локальные добавки нужно **сводить по `id`**, иначе будут дубли (так было, исправлено).

## 4. Отправка кадра

`POST /api/rolls/<rollId>/frames`, тело `multipart/form-data`:

| Поле | Значение |
| --- | --- |
| `file` | файл картинки (JPEG, PNG, TIFF, WebP...) |
| `idx` | целое ≥ 1: `firstIdx + позиция`. При повторе того же файла отправлять **тот же** `idx` |

Прогресс по кадру берётся из `XMLHttpRequest.upload.onprogress` (у `fetch` прогресса отправки нет).

Ответы (JSON):

| Статус | Тело | Что показать |
| --- | --- | --- |
| 200 | `{ "status": "ok", "id", "w", "h" }` | кадр принят |
| 200 | `{ "status": "exists" }` | кадр с этим `idx` уже принят раньше (повтор после обрыва): считать успехом |
| 401 | `{ "error": "auth" }` | сессия кончилась, войти заново |
| 404 | `{ "error": "roll" }` | плёнки нет или она чужая |
| 400 | `{ "error": "form" }` | нет `file` или `idx` |
| 413 | `{ "error": "size" }` | файл больше лимита (40 МБ, `MAX_FILE_MB`) |
| 413 | `{ "error": "quota" }` | исчерпан лимит места на пользователя (`USER_QUOTA_GB`, на проде 5 ГБ) |
| 415 | `{ "error": "format" }` | не удалось прочитать картинку |
| 500 | `{ "error": "storage" }` | сервер не смог сохранить файл |

Повторять отправку после сбоя можно любую (кроме `size`, `quota`, `format`: они повторятся). Обрыв сети
(`xhr.onerror`) тоже повод для повтора. Тексты для пользователя в форме сейчас лежат в словаре `ERRORS`.

## 4а. Импорт по ссылке (Яндекс Диск)

Источник кадров, а не отдельный сценарий: работает и для новой плёнки, и для существующей. В форме это третья
кнопка в блоке выбора файлов. Сервер сам скачивает файлы с Диска и принимает их тем же путём, что и загрузку
с компьютера (`lib/photos/ingest.ts`), поэтому форма файлов не отправляет, а только спрашивает состояние.

```ts
previewImportAction(url: string): Promise<
  | { ok: true; name: string; files: { name: string; size: number }[]; totalBytes: number; skipped: number; tooBig: number }
  | { ok: false; error: string }>     // error: готовый русский текст
startImportAction(input: { url: string; rollId: number | null; roll: NewRollInput | null }): Promise<
  | { ok: true; importId: string; rollId: number; count: number }
  | { ok: false; error: string }>
retryImportAction(importId: string): Promise<boolean>   // повторяет сразу все сбойные файлы
```

- `previewImportAction` ничего не скачивает и не создаёт: только список картинок по ссылке. `name` — название папки
  на Диске, по нему форма подсказывает плёнку и дату так же, как по названию перетащенной папки.
- Принимаются только публичные ссылки Яндекс Диска (`disk.yandex.ru`, `yadi.sk`, `disk.360.yandex.ru`), `https`.
  Берутся картинки из самой папки, вложенные папки не обходятся. `skipped` — не картинки и папки, `tooBig` — больше лимита.
- `startImportAction` заново берёт список на сервере (клиенту не доверяет), создаёт плёнку (всегда «только я»)
  или берёт существующую, резервирует номера кадров и запускает фоновую работу.
- Импорт идёт в два шага. Сначала сервер берёт у Диска уменьшенные копии (до 1280 px) и создаёт по ним временные
  кадры: плёнка видна через несколько секунд. Потом по одному приходят оригиналы и заменяют временные копии настоящими.
- Ход: `GET /api/imports/<importId>` →
  `{ rollId, finished, total, shown, done, failed, items: [{ name, size, status, error, shown }] }`.
  `shown` — сколько кадров уже видно в плёнке, `done` — сколько оригиналов принято.
  `status` файла: `queued` (ещё ничего), `preview` (кадр в плёнке, оригинал впереди), `working` (качается оригинал),
  `done`, `error`. `error` — те же коды, что у отправки кадра, плюс `download`.
  Форма опрашивает адрес раз в 1,5 секунды, пока `finished` не станет `true`.
- Если оригинал принять нельзя совсем (нет места, файл больше лимита, не читается), временный кадр стирается:
  кадров без оригинала в архиве не остаётся. При сбое сети кадр остаётся временным, шаг можно повторить.
- Импорт идёт на сервере и не зависит от вкладки. После перезапуска сервера задание подхватывается при следующем опросе.

## 5. Правка и удаление в плёнке (`app/rolls/[id]/actions.ts`)

```ts
saveRollAction(id: number, edit: RollEdit): Promise<boolean>
setRollVisibilityAction(id: number, visibility: "private" | "link" | "public"): Promise<boolean>
deleteRollAction(id: number): Promise<boolean>         // удаляет плёнку, её кадры и файлы; необратимо
deleteFrameAction(frameId: string): Promise<boolean>   // кадр помечается удалённым, файлы остаются

interface RollEdit {
  title: string | null;        // null = название собирается автоматически
  description: string;
  filmId: string; cameraId: string;
  iso: number | null; format: "35" | "120";
  month: number; year: number;
}
```

Доступ к плёнке меняется отдельным действием, а не вместе с полями папки: на странице плёнки это своя кнопка
слева от «Изменить»: значок ссылки и текущее значение в подписи (`VISIBILITIES[].short` из `lib/catalog.ts`). «Удалить» лежит
в окне правки и требует подтверждения: вместе с плёнкой стираются все кадры, файлы и задания импорта, место в лимите
освобождается.

Действия возвращают `false`, если не вошли, плёнка/кадр чужие или данные не прошли проверку. Правки экран
показывает сразу (`useOptimistic`), при `false` откатывает и сообщает пользователю.

Доступ к плёнке (`visibility`): `private` только автор; `link` любой по ссылке `https://<сайт>/s/<shareKey>`;
`public` любой, плёнка видна на странице автора `/u/<handle>`. `Roll.shareKey` приходит на клиент только автору плёнки.
Страница плёнки получает: `roll`, `frames`, `cameras`, `films`, `canEdit` (это автор), `backHref` (куда ведёт «назад», может не быть).

## 6. Что нельзя ломать во фронте

- **Картинки.** Адреса кадров остаются `/photos/f/<id>.jpg` (лента) и `/photos/l/<id>.jpg` (на весь экран): `feedSrc` и
  `fullSrc` из `lib/catalog.ts`. Их отдаёт сервер **с проверкой доступа по cookie**. Поэтому `next/image` нужно
  использовать только с `unoptimized`: оптимизатор запрашивает картинку без cookie и получит 404 для закрытых плёнок.
- **Выход и профиль.** Меню в шапке (`UserMenu.tsx`) вызывает `signOutAction` из `app/login/actions.ts`; шапка получает
  `user` из `app/layout.tsx` (`{ name, handle, avatarUrl } | null`).
- **Вход.** `/upload` и `/rolls` для гостя ведут на вход; ссылки на плёнки «по ссылке» открываются через `/s/<ключ>`.
- **Новые плёнки всегда «только я»**; изменить это может только автор в форме «Изменить» плёнки.
- Из клиентских компонентов нельзя импортировать `lib/db`, `lib/auth`, `lib/storage`, `lib/photos/*` (серверный код).
