# Бриф MVP: архив плёночных фото

## Цель
Один сайт, где плёночные кадры видны сразу, без прохода через папки Яндекс Диска. Лента для случайных встреч с кадрами, папки для целенаправленного просмотра. Друзья смотрят по ссылке.

## Кто что может
- **Зритель:** сайт публичный, только просмотр.
- **Владелец:** вход в админку (простой вход для одного человека) и загрузка плёнок.
- **Дальше (см. «После MVP»):** у каждого пользователя свой аккаунт и своя лента, которой можно поделиться ссылкой только для чтения.

## Данные

### Плёнка (папка)
- Плёнка из справочника (можно «Не знаю / не указана»), формат, ISO
- Камера (запоминается, можно добавить новую)
- Месяц и год (только месяц начала, без диапазона; если плёнка снималась дольше, это можно написать в описании)
- Описание (в нём же можно писать место или поездку)
- Название собирается автоматически: «Kodak Gold 200 · июль 2025». Если ISO съёмки отличается от заявленного на плёнке, оно дописывается

### Кадр
- Оригинал, облегчённая копия для ленты, размеры и пропорция
- Цвет и яркость (считаются при загрузке)
- Принадлежит ровно одной плёнке

### Справочники
- **Плёнки:** Kodak Color Plus 200, Kodak Gold 200, Lucky Color 200, Perspectiva Super-F 200, Tasma T-42L, «Луч» (цветная), «Два луча» 400, Kodak Portra 160/400/800 и популярные западные. Для разбора названий папок хранятся синонимы написания (KodakGold = Kodak Gold, Lucky200 = Lucky 200). Пользовательские плёнки добавляются и попадают в список
- **Камеры:** добавляются владельцем, последняя выбранная запоминается

## Экраны

### 1. Лента
- Все кадры вперемешку. Порядок фиксируется один раз за визит, есть кнопка «перемешать»
- Цвет и вайб используются только здесь: переключатель режимов «Вперемешку» (по умолчанию) и просмотр по цвету или настроению (например тёплые, холодные, тёмные, светлые, ч/б). Точный набор режимов уточним на прототипе
- Masonry без обрезки кадров: 4 колонки на десктопе, 2 на мобильном
- Часть кадров занимает две колонки (случайно, но не подряд), редкие пустые клетки с подписью плёнки
- В углу кадра маленькая кнопка-плёнка, всегда видна, ведёт в папку
- Обычный вертикальный скролл

### 2. Папки
- Плоский список плёнок карточками
- Фильтры: камера (обязательно), плёнка, год
- Сортировка по дате
- Цвет и вайб здесь не используются

### 3. Плёнка
- Шапка: название, камера, ISO, месяц и год, описание
- Все кадры плёнки

### 4. Кадр на весь экран
- Листание стрелками и свайпом
- Подпись: камера, плёнка, ISO, ссылка на папку

### 5. Загрузка (только владелец)
- Форма: плёнка, ISO и камера выбираются из списков, год и месяц, описание, файлы или папка перетаскиванием
- Два сценария: новая плёнка или добавить кадры в существующую
- При перетаскивании папки поля предзаполняются по названию (только как подсказка), для отдельных файлов заполняется вручную
- Прогресс по каждому кадру, повторная загрузка при сбое
- *(необязательно)* Мягкая проверка по EXIF: если у файла явно стоит модель телефона или цифровой камеры без сканера, показать подсказку «Похоже на цифровое фото, всё верно?». Не блокирует загрузку — часть сканов приходит вовсе без EXIF, метод ненадёжен и годится только как подсказка себе. Основной фильтр от нефильмовых фото — обязательные поля плёнки, формата и ISO в форме, без них плёнку не создать

## Внешний вид
- Светлый тёплый бумажный фон (пробуем, при необходимости переделаем)
- Кадры целиком, тонкая рамка или тень для светлых кадров
- Артовость через ритм размеров и пустоты, а не через искажение кадров
- Принцип: творческая сетка снаружи, предсказуемая навигация внутри

## Объём и техника
- Сейчас около 18 плёнок (примерно 650 кадров, ~3,5 ГБ), дальше 12–16 плёнок в год (около 3 ГБ в год)
- Один кадр 5–6 МБ. Оригиналы хранятся, лента использует облегчённые копии (200–400 КБ)
- Загрузка одной плёнки около 200 МБ: параллельная загрузка, прогресс, докачка
- Веб-сайт, мобильная версия обязательна

## Не входит в MVP
Чужие ленты, комментарии, лайки, подписки, интеграция с Яндекс Диском, AI-теги, тёмная тема, переименование папки, скачивание оригиналов.

## После MVP
Порядок важен: каждый следующий этап опирается на предыдущий.

### Этап 1. Серверное хранилище
- Оригиналы и облегчённые копии лежат на сервере (объектное хранилище), а не локально
- Нужно решить заранее: лимит места на пользователя, потому что при росте числа пользователей хранение (около 3 ГБ в год на человека) становится главной статьёй расходов

### Этап 2. Аккаунты и личные ленты
- У каждого пользователя свой аккаунт, своя лента, свои плёнки и свои справочники камер
- Данные одного пользователя не видны другому, кроме как через ссылку (см. ниже)
- **Ссылка на свою ленту только для чтения:** случайный непубличный адрес, который можно отозвать и пересоздать. Без входа зритель видит ленту и папки, но ничего не может менять
- Вход: email или вход через внешний сервис (решить на старте этапа)
- Лента и папки остаются теми же экранами, что в MVP, но показывают только кадры владельца

### Этап 3. Импорт из облаков
Все источники у пользователей приватные (Яндекс Диск, Google Фото, файлы на устройстве), поэтому импорт идёт через вход в аккаунт самого пользователя (OAuth), а не по публичным ссылкам.
- **Загрузка с устройства** остаётся основным способом для всех, работает уже в MVP
- **Яндекс Диск:** первый внешний источник. Пользователь подключает аккаунт, выбирает папки, сервер скачивает кадры сам, не через браузер. Названия папок предзаполняют форму, как при загрузке с устройства
- **Google Фото:** отдельным шагом после Яндекса. Доступ к библиотеке у Google ограничен и требует выбора фото пользователем через их собственное окно, условия надо сверять с актуальной документацией перед стартом
- Общий принцип: у импорта единый интерфейс «источник», внутри разные коннекторы, чтобы добавлять новые сервисы без переделки остального
- Для каждого коннектора: хранение токенов, отзыв доступа, обработка ошибок и лимитов, повторная попытка при сбое

## Принятые решения
- Период: только месяц и год начала
- Portra: 160/400/800 в справочнике, у владельца Portra 160
- Цвет и вайб: только в ленте, в папках не используются

## Открытые вопросы
Пока нет. Уточнятся на прототипе: набор режимов цвета и вайба в ленте, точные правила размеров кадров и пустых клеток.

## Следующий шаг
