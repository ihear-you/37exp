@AGENTS.md

## Проект

«[37exp]» — архив плёночных кадров (лента + папки), на русском. Next.js 16 (App Router, Turbopack), React 19, Tailwind v4, TypeScript. Фронт и бэкенд в одном приложении: база SQLite (`better-sqlite3`), вход через Яндекс/Google (`arctic`), обработка кадров (`sharp`). Бриф — `brief-mvp.md`, обзор экранов и настроек ленты — `README.md`, контракт формы загрузки и правки плёнки — `docs/upload-form-contract.md`.

Next здесь не тот, что в обучающих данных: перед правкой роутинга/кэша/`next/image` сверяйся с `node_modules/next/dist/docs/`. Уже встреченное: route config `dynamic` нет (вместо него `connection()` из `next/server`), из `route.ts` нельзя экспортировать ничего, кроме обработчиков, типы страниц — `PageProps<"/route">` (после удаления `.next` их возвращает `npx next typegen`).

## Команды

```bash
npm run dev      # http://localhost:3000 (конфиг превью: .claude/launch.json, имя "photo-lab")
npm run build
npm run lint     # eslint с react-hooks: запрещает setState/мутации в эффектах и во время рендера
npx tsc --noEmit # отдельной команды typecheck нет
npm run db:reset # удаляет data/plenka.db; база создастся и заполнится заново при следующем запуске
npm run import   # scripts/import-photos.mjs: из папок в SOURCES делает seed/photos/{f,l} и lib/photos/frames.json
```

Тестов нет. Второй `next dev` в той же папке не запустится, а порт 3000 может быть занят сервером из другой папки проекта (основная папка и worktree): проверь, чей сервер отвечает, прежде чем верить результату.

## Архитектура

- **Данные — SQLite, вход только через `lib/db/index.ts`.** Страницы, серверные действия и route handlers вызывают асинхронные функции фасада (`getMy…(userId)`, `getRollForViewer`, `getPublicProfile`, `createRoll`, `addFrame`…). Весь SQL — в `queries.ts` (синхронный), файл базы — `connection.ts` (WAL, соединение на `globalThis`), таблицы — `schema.ts`. Объект `background` в фасаде — те же операции без `connection()`, для фоновых задач вне запроса. Из клиентских компонентов `lib/db`, `lib/auth`, `lib/storage`, `lib/photos/*`, `lib/import/*` не импортируются: данные приходят пропсами.
- **Миграции** — массив `MIGRATIONS` в `lib/db/schema.ts`, номер в `PRAGMA user_version` (сейчас 12). Применяются сами при открытии базы, в том числе на проде при деплое. Старые шаги не правятся, новый шаг добавляется в конец.
- **Стартовые данные.** Пустая база заполняется из `lib/catalog.ts` (`ROLLS`, `CAMERAS`) и `lib/photos/frames.json`, их файлы лежат в `seed/photos` (в git). `PLENKA_SEED=0` отключает (так на проде). `FILMS` в `catalog.ts` — общий справочник плёнок, свои плёнки пользователя лежат в таблице `user_films` (id вида `u-xxxxxxxx`). `id` плёнки в `ROLLS` и номер в `SOURCES` скрипта импорта должны совпадать.
- **Пользователи и вход** (`lib/auth/`). Войти может любой, у каждого свой архив. В cookie `session` случайный токен, в базе его sha256. Вход держится 90 дней с последнего захода: запись в базе продлевает `getViewer`, cookie в браузере — `proxy.ts` в корне (страницы и действия при отрисовке cookie менять не могут), оба не чаще раза в сутки (пометка `session_fresh`). `proxy.ts` токен не проверяет и в базу не ходит; названия cookie в его `matcher` записаны строками и должны совпадать с `lib/auth/cookie.ts`. `getViewer()` — кто смотрит; `requireUser()` — проверка в серверных действиях. Кнопки входа показываются для сервисов, чьи ключи заданы; на проде настроен только Яндекс. Почта из `OWNER_EMAILS` при первом входе забирает себе стартовый архив (пользователь 1), других прав у неё нет. Аккаунты сервисов сводятся по почте (`oauth_accounts`).
- **Доступ к плёнке** — одно правило на весь сайт, `lib/access.ts` (`canView`): `private` (только автор), `link` (по ссылке `/s/<shareKey>`: ключ кладётся в cookie `rk`, дальше редирект на `/rolls/<id>`), `public` (видна на `/u/<handle>`) больше не выбирается — в `VISIBILITIES` только два варианта, миграция 11 перевела такие плёнки в `link`, а на `/u/<handle>` ничего не ведёт (меню под аватаром: имя и «Выйти»). Новая плёнка всегда `private`; доступ меняется отдельным действием `setRollVisibilityAction`, не вместе с полями папки. Чужому и несуществующему отвечаем одинаково, 404.
- **Файлы кадров вне `public/`** (`lib/storage/index.ts`): `storage/feed|full/<id>.jpg` и `storage/originals/<user>/<id>.<ext>`, запасной путь — `seed/photos`. Адреса `/photos/f|l/<id>.jpg` отдаёт `app/photos/[size]/[file]/route.ts` с проверкой доступа по cookie, поэтому `next/image` для кадров — только с `unoptimized` (оптимизатор ходит без cookie и получит 404). Оригинал скачивается из просмотра на весь экран (`Lightbox.tsx`, кнопка есть только у кадров с `Frame.original`) по `/photos/o/<id>` (`app/photos/o/[id]/route.ts`): та же проверка доступа, файл потоком (`openOriginal`), имя «название плёнки — номер кадра». Там же автор поворачивает кадр по часовой (`rotateFrameAction` → `lib/photos/rotate.ts`): поворачивается сам оригинал — JPEG без потерь, только отметкой EXIF Orientation (`lib/photos/orientation.ts`), PNG/TIFF/WebP пересохраняются без потерь, HEIC нельзя; копии делаются заново, `frames.version` растёт и попадает в адрес копий (`feedSrc(id, v)`/`fullSrc(id, v)`), чтобы браузер не показал старую.
- **Загрузка** (`/upload`, `UploadFlow.tsx`) — два шага, без полей до старта. Сначала две плитки (`UploadSources.tsx`): с устройства (выбрать или перетащить файлы или папку) или по ссылке с Яндекс Диска. Как только кадры выбраны, загрузка стартует сама: новая папка создаётся по догадкам (плёнка, ISO и месяц — `parseFolderName` по названию папки или папки на Диске, камера и формат — как у последней плёнки, иначе «не знаю», без камеры, текущий месяц). Рядом с кадрами карточка «Что это за плёнка?» (название, плёнка, камера, период, описание): «Сохранить и продолжить» — `saveRollAction` и переход в папку, «Не сохранять» — в папку без изменений; «Выбрать другие фото» отменяет загрузку (`cancelJob`) и стирает созданную ею папку. Поля общие с окном «Изменить» — `RollFields.tsx`: плёнка и камера — ввод с подсказками (справочники `FILMS` с форматами `formats` и `lib/cameras.ts`, свои — первыми; вписанное своё заводится при сохранении, `resolveFilmAndCamera`), формат выбирается строкой подсказки или кнопкой в поле, период — сетка месяцев (`PeriodPicker`). Камера необязательна. Добавить кадры в существующую папку через `/upload` нельзя (будет кнопкой на странице папки). Период съёмки: `rolls.year/month` — начало, `end_year/end_month` — конец или NULL (сняли за месяц); подпись — `periodLabel`, поле — `PeriodPicker` (`RollFields.tsx`), проверка — `validPeriod`. `startUploadAction` создаёт плёнку и резервирует номера кадров. Дальше загрузку ведёт загрузчик на весь сайт (`lib/upload-queue.ts`, ход в углу — `UploadIndicator.tsx` в layout): из формы можно уйти, кадры продолжат уходить. Оригиналы идут кусочками по 1 МБ, не больше двух в пути на всю вкладку (`/api/uploads/<id>/parts`, затем сборка кадра в `/api/uploads/<id>/frames`; недособранное лежит в `storage/parts/`): целые файлы забивали единственное соединение браузера, и переходы по сайту ждали до 15–20 с. Повтор безопасен, оборвавшийся кусочек повторяется сам. Загрузка принимает кадры только со своими номерами (`uploads.first_idx` + `expected`), недособранных файлов у неё не больше `MAX_OPEN_PARTS`, а незаконченных загрузок у человека — не больше `MAX_OPEN_UPLOADS` (`lib/uploads.ts`): иначе кусочками можно было забить диск; импорт загрузчик опрашивает. Форма только запускает загрузку и показывает её (`setShownInForm`). Загрузка целиком или никак, и с устройства, и импорт с Диска (у импорта номер загрузки = номер задания) (`lib/uploads.ts`, таблица `uploads`, `frames.upload_id`): закрыли вкладку до конца — загрузчик шлёт `sendBeacon` на `/api/uploads/<id>/abort`, кадры этой загрузки и созданная ею плёнка стираются; дошло всё — `/complete`; брошенные без вестей разбирает уборщик (с устройства — 30 минут, импорт — 3 минуты без опросов). Перед закрытием вкладки браузер переспрашивает (`beforeunload`); переходы внутри сайта загрузку не прерывают. Журнал шагов: консоль браузера («[загрузка]») и журнал службы (`lib/log.ts`). Приём кадра — `lib/photos/ingest.ts`, уменьшенные копии и цвет — `process.ts` (через общую очередь сервера `queue.ts`: по умолчанию одна обработка за раз, `PHOTO_JOBS`; там же поворот), лимиты — `limits.ts` (`MAX_FILE_MB`, `USER_QUOTA_GB`). Удалённый кадр остаётся в базе и на диске с `deleted_at`; удаление плёнки (`deleteRollAction`) стирает кадры и файлы насовсем.
- **Импорт с Яндекс Диска** (`lib/import/`). `yandex.ts` — открытый API публичных ссылок без токена; сервер ходит только на адреса из списка разрешённых и проверяет каждый редирект (защита от SSRF — не ослаблять). `runner.ts` — фоновая работа в два шага: по уменьшенным копиям с Диска создаются временные кадры (`frames.provisional = 1`), затем приходят оригиналы и заменяют их. Состояние — таблицы `imports`, `import_items`, форма опрашивает `GET /api/imports/<id>`; после перезапуска сервера задание подхватывается при следующем опросе. Вложенные папки не обходятся.
- **Главная и первый вход.** Гость видит `WelcomeReel` с одной кнопкой «Войти через …» (сразу к сервису входа; «Войти» в шапке на этом экране скрыта). Вошедший без единой плёнки (первый вход или удалил все папки) уходит с `/` на `/rolls`, где вместо списка — те же плитки, что на `/upload` (`UploadSources.tsx`). Выбранные там кадры ждут `/upload` в памяти вкладки (`lib/upload-handoff.ts`), и загрузка начинается сразу при открытии. Вошедший с кадрами видит ленту; плёнки есть, но все пустые — лента показывает заглушку «Пока нет загруженных фотографий», а «Папки» — обычный список. Навигация видна, пока есть хоть одна плёнка (`hasArchive` в `lib/nav.ts`). `WelcomeReel` без `signIn` (заставка вошедшего) остался только на `/preview-welcome`. **Своей страницы входа нет:** «Войти через …» в шапке (`UserMenu`) ведёт сразу к сервису входа и обратно на ту же страницу (`next`); новый аккаунт (первый вход, `findOrCreateOAuthUser().created`) вместо этого попадает на `/rolls` — пустое состояние с плитками, `/upload` и `/rolls` гостя — туда же (`signInHref`), старый `/login` перенаправляется на главную (`next.config.ts`). Неудачный вход возвращает на главную с `?login=<причина>`, текст показывает заставка.
- **Переходы по сайту.** Главная лежит в группе `app/(feed)/` ради своей заготовки: `loading.tsx` в `(feed)`, `rolls/` и `rolls/[id]/` (`Skeletons.tsx`) показываются сразу после клика, пока идут данные. Из-за потоковой отдачи `redirect` и `notFound` на этих страницах приходят с кодом 200 (переход делает браузер, `noindex` остаётся). `next.config.ts`: `experimental.staleTimes.dynamic = 30` — открытые за 30 секунд страницы при возврате берутся из памяти браузера; `revalidatePath` и `router.refresh` её сбрасывают. Окно загрузки обновляет страницу не чаще раза в 10 секунд и только там, где видны новые кадры, а в конце загрузки — сразу.
- **Лента** — `lib/feed.ts` (`planFeed`: ритм крупных/широких кадров и подписей, тёплый/холодный уклон) + `lib/masonry.ts` (раскладка без обрезки) + `Masonry.tsx`/`Feed.tsx`. Порядок хранится только в памяти вкладки (`lib/persist.ts`, kind `"memory"`) и меняется на каждую загрузку.
- **`lib/persist.ts`** — мини-хранилище на `useSyncExternalStore`: на сервере и при первой отрисовке отдаёт запасное значение, чтобы гидрация не расходилась. Тот же приём (детерминированный `SEED`, `lib/rand.ts: mulberry32`) нужен везде, где SSR и клиент должны нарисовать одно и то же.
- **Шапка и навигация** считаются в одном месте, `lib/nav.ts` (`useShowNav`, `useIsWelcomeScreen`), и используются и в `SiteHeader` (десктоп), и в `BottomBarNav` (ниже `md`) — условия нельзя дублировать. Пустое состояние (`hasArchive === false` на `/`, а также служебная `/preview-welcome`): без кнопок Лента/Папки/Загрузить, хедер прозрачный. Аватар и выход — `UserMenu.tsx` (`signOutAction`), `user` приходит из `app/layout.tsx`.
- **Удаление кадра** (просмотр на весь экран, в ленте и в папке) — сразу, без подтверждения: кадр только помечается `deleted_at`, и 7 секунд в углу висит «Кадр удалён · Отменить» (`lib/undo.ts`, плашка в `UploadIndicator.tsx`, возврат — `restoreFramesAction`); несколько удалений подряд копятся в одну плашку. Угол с плашкой и окном загрузки лежит поверх просмотра (`z-[60]`).
- **Страница плёнки** (`RollDetail.tsx`): правки показываются сразу через `useOptimistic` и откатываются, если действие вернуло `false`. Слева от «Изменить» — кнопка доступа (значок ссылки + `VISIBILITIES[].short`), «Удалить» папку — в окне правки с подтверждением.
- **Заставка — `WelcomeReel.tsx`**: полноэкранный (`fixed inset-0`) коллаж на CSS-keyframes (`tile-burst` в `globals.css`), плитки по зонам 4×4, рост от центра экрана через `transform-origin` в процентах, перезапуск по `onAnimationEnd` + `key`. Фото берёт из `lib/editorial.ts`; без них плитки остаются цветными заглушками (локальные кадры закрыты доступом, запрашивать их нельзя). Ниже `md` подпись Unsplash стоит под кнопкой, от `md` — в правом нижнем углу. Dev-страницы: `/preview-welcome` (заставка вошедшего), `/preview-welcome?guest` (заставка гостя), `/preview-empty` (пустые папки) — рисуются независимо от наличия кадров.
- **Фото заставки и веера** (`lib/editorial.ts`, список с авторами — `lib/editorial.json`, файлы — `public/editorial/`): фото с Unsplash лежат на самом сайте, потому что `images.unsplash.com` из России без VPN не открывается (вместо фото были цветные квадраты). Лицензия Unsplash это разрешает. Обновить подборку — `npm run editorial -- <id> …` (`scripts/editorial-photos.mjs`, нужен `UNSPLASH_ACCESS_KEY` в `.env.local`, сайту ключ не нужен); первые четыре — веер (`getFanPhotos`: по краям — два самых цветастых по `vivid`, яркости по пикселям, её считает скрипт). Не возвращай показ картинок прямо с Unsplash. Подпись «Фото сообщества Unsplash» оставляем.
- **Стили**: цвета и радиусы — токены в `:root` в `app/globals.css` (`--round-control`, `--round-frame`, проброшены в Tailwind как `rounded-control`/`rounded-frame` через `@theme inline`). Курсива нет; Anton — только логотип (`font-logo`), весь текст — Inter Tight (400), заголовки экранов — он же Medium (`font-display`, 500).

В git не попадают: `.env*` (кроме `.env.example`), `data/*.db`, `data/unsplash-cache.json`, `storage/`.

## Подводные камни

- **Worktrees:** у каждого worktree свои `.env.local`, `data/plenka.db` и `storage/` (все gitignored) — в новом нет ключей входа, архив пустой. Stash общий для всех worktree: не используй голый `git stash`/`pop`.
- **Старое не трогать:** `photolab.db` в корне и `public/uploads/` остались от ранней версии и кодом не используются; не удаляй и не меняй их без просьбы.
- **Проверка в превью под входом:** cookie `session` привязана к `localhost` без порта, сервер на другом порту её перезапишет. Перед выполнением JS на странице проверь `location.origin`: после редиректа на вход это может быть уже сайт Яндекса.
- **Проверка анимации в превью:** в скрытой панели браузера `document.hidden === true`, и скриншоты выходят чёрными — это не пустота, сначала выведи вкладку на передний план.
- **zsh:** glob без совпадений (`--include=*.ts`, `.env*`) роняет команду — бери шаблоны в кавычки.
