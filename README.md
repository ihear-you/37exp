# [37exp]

**Сайт: [37exp.ru](https://37exp.ru)**

Архив плёночных кадров: лента для случайных встреч, папки для целенаправленного просмотра.
Бриф: [brief-mvp.md](brief-mvp.md).

Фронт и бэкенд в одном приложении на Next.js. Плёнки, камеры и кадры
хранятся в SQLite (`data/plenka.db`), файлы кадров лежат на диске сервера (`storage/`). Пользователей несколько:
каждый, кто вошёл через Яндекс или Google, получает свой архив, загружает в него кадры (с компьютера или по ссылке
с Яндекс Диска) и сам решает, кто видит каждую его плёнку (см. «Доступ к плёнкам»).

## Запуск

```bash
npm install
npm run dev
```

Сайт запустится у вас на компьютере по адресу `http://localhost:3000` (работает только пока идёт `npm run dev`; рабочий сайт — [37exp.ru](https://37exp.ru)).

База создаётся сама при первом открытии сайта: файл `data/plenka.db` (не в git) заполняется стартовым набором, двумя
плёнками и 72 кадрами из `lib/catalog.ts` и `lib/photos/frames.json`. Начать с чистого листа (все плёнки, правки и
пользователи из базы пропадут, файлы в `storage/` останутся): остановите сайт и выполните `npm run db:reset`, база
создастся заново. Другое место для файла: переменная `PLENKA_DB_PATH`. Пустая база без стартового набора:
`PLENKA_SEED=0` (так на сервере).

Без ключей в `.env.local` сайт запустится, но войти будет нельзя, а значит, и увидеть ленту: см. «Вход через Яндекс
или Google». Фото заставки лежат на сайте (`public/editorial`); `UNSPLASH_ACCESS_KEY` нужен только чтобы обновить подборку (`npm run editorial -- <id> …`).

## Доступ к плёнкам

У каждой плёнки есть доступ. Автор меняет его на странице плёнки отдельной кнопкой слева от «Изменить»: на ней значок
ссылки и текущее значение («Только я» или «По ссылке»).

| Доступ | Кто видит |
| --- | --- |
| Только я (по умолчанию) | только автор; для остальных плёнки как будто нет (404) |
| Все, у кого есть ссылка | любой, кто пришёл по ссылке `/s/<ключ>` (ссылка показана в окне доступа, там же «Копировать») |

Третьего варианта «Видна всем» (плёнка на странице автора `/u/<адрес>`) больше нет: такие плёнки миграция 11 перевела
в «по ссылке». Сама страница `/u/<адрес>` в коде осталась, но никуда на неё не ведёт и показывает только `public`.

Новая плёнка всегда создаётся с доступом «только я», при загрузке выбрать другой нельзя.

Правило одно на весь сайт: `lib/access.ts` (`canView`). Смотреть чужие плёнки не нужно входить. Лента и «Папки» показывают
только ваши плёнки. Главная без входа показывает заставку с одной кнопкой «Войти через Яндекс». После первого входа, пока плёнок нет, открывается страница «Папки» с двумя плитками: загрузить кадры с устройства или по ссылке с Яндекс Диска. В меню под аватаром —
имя и «Выйти».

**Файлы кадров** лежат на диске сервера в `storage/` (оригиналы, копии для ленты и на весь экран; папка не в git),
а кадры стартового набора в `seed/photos`. Из `public/` они убраны: картинки `/photos/f|l/<id>.jpg` отдаёт
`app/photos` и только тем, кто вправе видеть плёнку (`lib/access.ts`). Ссылка «по ссылке» имеет вид `/s/<ключ>`:
ключ запоминается в cookie зрителя, по нему же открываются картинки. Хранилище — один файл `lib/storage/index.ts`
(его можно переписать под облако). Папку можно вынести: `PLENKA_STORAGE_DIR`.

Загрузка (`/upload`) идёт в два шага и без полей до старта: сначала две плитки — с устройства (выбрать или перетащить
файлы или папку) или по ссылке с Яндекс Диска. Как только кадры выбраны, загрузка начинается, а новая папка создаётся
по догадкам: плёнка, ISO и месяц — по названию папки, камера и формат — как у прошлой плёнки. Пока идут кадры, рядом
карточка «Что это за плёнка?» (плёнка, камера, формат, начало и конец съёмки, описание): её можно поправить или
пропустить, всё меняется потом в «Изменить» на странице папки. Файлы отправляет загрузчик `lib/upload-queue.ts`
кусочками по 1 МБ, по два в пути (`app/api/uploads/[id]/parts`, сборка кадра — `app/api/uploads/[id]/frames`), с
прогрессом и повтором по каждому кадру. Камеру и плёнку можно вписать свои, они сохранятся в архиве пользователя. Лимиты (в `.env.local`):
`MAX_FILE_MB` (по умолчанию 40) и `USER_QUOTA_GB` (по умолчанию 10 на пользователя). Регистрация открытая, поэтому
лимит нужно держать.

Удаление: кадр удаляется со страницы плёнки и остаётся в базе и на диске с отметкой. Папка удаляется кнопкой «Удалить»
в окне «Изменить» (с подтверждением) насовсем: вместе с кадрами, файлами и заданиями импорта, место в лимите
освобождается.

Импорт по ссылке: вторая плитка на странице загрузки, «По ссылке с Яндекс Диска». По публичной ссылке сервер сам скачивает
кадры (`lib/import/yandex.ts`, без входа в Яндекс и без ключей) и принимает их тем же путём, что и обычную загрузку
(`lib/photos/ingest.ts`). Работа идёт в фоне в два шага (`lib/import/runner.ts`): сначала по уменьшенным копиям
с Диска создаются временные кадры (плёнка видна через несколько секунд, у кадра `provisional = 1`), потом
по одному приходят оригиналы и заменяют копии настоящими. Состояние лежит в базе
(таблицы `imports`, `import_items`) и отдаётся через `app/api/imports/[id]`. Загрузка, и с устройства, и с Диска, идёт в фоне (`lib/upload-queue.ts`): из формы можно уйти на любую страницу сайта, ход виден в углу экрана. Но целиком или никак (`lib/uploads.ts`): если закрыть вкладку до конца, её кадры и созданная ею папка стираются, импорт останавливается. Сервер ходит
только на адреса Яндекса, включая каждый редирект.

## Вход через Яндекс или Google

Своей страницы входа нет: «Войти через …» в шапке и на заставке ведёт сразу к сервису входа и обратно на ту же страницу
(а тот, кто вошёл впервые, попадает на «Папки» с плитками загрузки)
(туда же ведут `/upload` и `/rolls`, пока вы не вошли). Берётся первый сервис с ключами в `.env.local` (Яндекс, потом
Google); хватит одного. Если вход не удался, сервис возвращает на главную с `?login=<причина>`, и заставка пишет её. Войти может любой, и у каждого свой архив. Почты в
`OWNER_EMAILS` задают владельца сайта: при первом входе он получает архив, который уже лежит в базе (плёнки из seed).
Впишите туда свою почту. Входите одним сервисом: если почты сервисов разные, второй вход будет считаться отдельным
человеком с пустым архивом.

### Яндекс (без карты)

1. Откройте [oauth.yandex.ru](https://oauth.yandex.ru/) под аккаунтом, которым будете входить, и нажмите «Создать приложение».
2. Тип приложения: для авторизации пользователей (после регистрации его поменять нельзя). Название: `37exp`.
3. Платформа: «Веб-сервисы». Callback URI #1: `http://localhost:3000/api/auth/yandex/callback` (порт должен совпадать
   с тем, на котором запущен сайт).
4. Доступы: адрес электронной почты (`login:email`), имя и фамилия (`login:info`), портрет пользователя (`login:avatar`).
5. Создайте приложение, скопируйте ID и пароль приложения в `.env.local`: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`.

### Google

Нужен проект в [Google Cloud Console](https://console.cloud.google.com/). Карта для этого не требуется: не активируйте
платный пробный период.

1. Настройте экран согласия («Google Auth Platform»): название `37exp`, тип «External», свою почту добавьте в
   «Test users» (пока приложение в режиме «Testing», войти смогут только они).
2. «Clients» → «Create client» → «Web application». В «Authorized redirect URIs» добавьте
   `http://localhost:3000/api/auth/google/callback`. Названия пунктов в консоли Google иногда меняются.
3. Скопируйте ключи в `.env.local`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

### Общее

Скопируйте `.env.example` в `.env.local`, заполните ключи и `OWNER_EMAILS`, перезапустите `npm run dev` (переменные
читаются при старте). `.env.local` в git не попадает. При первом входе владельца за ним закрепляются плёнки и кадры
из базы.

На сервере: в настройках приложения должен быть адрес возврата с доменом (`https://37exp.ru/api/auth/yandex/callback`
и/или `.../google/callback`), а в окружении `APP_URL=https://37exp.ru`. Сейчас на 37exp.ru настроен только Яндекс.
Для Google ещё нужно перевести экран согласия в «In production» (для базового профиля проверка не нужна).

## Что где

| Экран | Адрес | Файл |
| --- | --- | --- |
| Лента | `/` | `app/components/Feed.tsx`, `Masonry.tsx` |
| Папки | `/rolls` (мои) | `app/components/RollsBrowser.tsx`; пока плёнок нет: `UploadSources.tsx` |
| Страница автора | `/u/[handle]` | `app/u/[handle]/page.tsx` |
| Плёнка | `/rolls/[id]` (по доступу) | `app/rolls/[id]/page.tsx`, `app/components/RollDetail.tsx`; правка, доступ, удаление папки и кадра: `app/rolls/[id]/actions.ts` |
| Плёнка по ссылке | `/s/[key]` | `app/s/[key]/route.ts`: запоминает ключ и ведёт на плёнку |
| Кадр на весь экран | поверх ленты и плёнки | `app/components/Lightbox.tsx` |
| Загрузка | `/upload` (после входа) | `app/components/UploadFlow.tsx` (плитки — `UploadSources.tsx`), `app/upload/actions.ts`; приём кадра: `app/api/uploads/[id]/parts` и `/frames`, ход импорта: `app/api/imports/[id]`, загрузчик и индикатор: `lib/upload-queue.ts`, `UploadIndicator.tsx` |
| Вход и выход | своей страницы нет | «Войти через …» в шапке и на заставке ведёт сразу в `app/api/auth/[provider]/` (`signInHref` в `lib/auth/providers.ts`), выход — `app/auth/actions.ts`; меню с аватаром в шапке: `app/components/UserMenu.tsx` |
| Картинки кадров | `/photos/f\|l/<id>.jpg` | `app/photos/[size]/[file]/route.ts`: отдаёт файл только тому, кто вправе видеть плёнку |

Что именно форма загрузки и страница плёнки вызывают на сервере, описано в
[docs/upload-form-contract.md](docs/upload-form-contract.md).

Логика без интерфейса лежит в `lib/`:

- `db/`: слой данных на SQLite (better-sqlite3).
  - `index.ts`: единственная точка доступа для страниц и серверных действий (плёнки, кадры, лента, правка, доступ,
    удаление, загрузка, импорт, вход). Функции асинхронные и отдают простые объекты, чтобы позже заменить
    SQLite на размещённую базу, переписав только `queries.ts` и `connection.ts`.
  - `queries.ts`: SQL-запросы. `connection.ts`: открытие файла. `schema.ts`: таблицы и миграции (`users`,
    `oauth_accounts`, `sessions`, `cameras`, `user_films`, `rolls`, `frames`, `imports`, `import_items`); миграции
    применяются сами при открытии базы. `seed.ts`: первичное заполнение. `user.ts`: пользователь с данными из seed,
    которого забирает владелец при первом входе. Чтение чужого идёт только через `getRollForViewer` и `getPublicProfile`
    (они проверяют `lib/access.ts`), «мои» функции работают с `userId` вошедшего.
  - Удалённый кадр остаётся в базе и на диске с отметкой `deleted_at`, просто нигде не показывается. Удалённая плёнка
    стирается целиком.
- `auth/`: вход и сессии. Вход держится 90 дней с последнего захода (`cookie.ts`; cookie продлевает `proxy.ts` в корне проекта).
  `session.ts`: сессия в cookie (в ней случайный токен, в базе только его sha256),
  `getViewer()` (кто смотрит) и `requireUser()` (проверка в серверных действиях: правит только своё). `config.ts`: переменные окружения,
  почты владельца сайта `OWNER_EMAILS`. `providers.ts`: Google и Яндекс на библиотеке `arctic`; новый способ входа — ещё один объект в `PROVIDERS`.
  `shares.ts`: ключи плёнок «по ссылке» в cookie зрителя.
- `access.ts`: кто вправе видеть плёнку и её кадры (`canView`).
- `storage/`: файлы кадров на диске (оригинал, копия для ленты, копия на весь экран).
- `photos/`: приём кадра (`ingest.ts`), уменьшенные копии и цвет (`process.ts`), лимиты (`limits.ts`).
- `import/`: импорт по ссылке с Яндекс Диска (`yandex.ts`: список и скачивание, `runner.ts`: фоновая работа).
- `editorial.ts` + `editorial.json`: фото Unsplash для заставки и веера, хранятся в `public/editorial` (с images.unsplash.com из России без VPN не грузится).
- `catalog.ts`: типы, общий справочник плёнок `FILMS` (свои плёнки пользователя лежат в базе), подписи доступов,
  сборка названия («Kodak Gold 200 · июль 2025»). Массивы `ROLLS`, `CAMERAS`, `FRAMES` в нём — стартовые данные
  для базы; `FRAMES` ещё даёт цвета плиток заставке (`WelcomeReel.tsx`), когда нет фото подборки.
- `feed.ts`: режимы ленты (вперемешку, по цвету, тёплые, холодные, светлые, тёмные, ч/б) и правила ритма.
- `masonry.ts`: раскладка сетки без обрезки кадров.
- `folder-name.ts`: подсказка по названию папки при загрузке.

## Дизайн

Тёмная тема, чёрный фон. Два шрифта:

- **Inter Tight** — весь текст на сайте (400) и заголовки экранов (500, Medium, класс `font-display`: название папки, заставка, «Загрузите плёнку», «Загрузка плёнки», «Что это за плёнка?»). Подключён в `app/layout.tsx`, переменная `--font-inter-tight`.
- **Anton** — только логотип «[37exp]» в шапке (`app/components/SiteHeader.tsx`, класс `font-logo`). В нём нет кириллицы, поэтому для русского текста не используется.

Курсив нигде не используется. Раньше для заголовков и названий плёнок был отдельный шрифт (Cormorant Garamond) — от него отказались в пользу одного шрифта на весь сайт; если это решение нужно будет пересмотреть, история и причины — в `git log`.

Цвета — переменные в `app/globals.css`, `:root`.

Навигация — в правом углу шапки (`app/components/SiteHeader.tsx`): Лента/Папки — переключатель в общей капсуле (`--paper-deep`), активный пункт светлее (`--paper-edge`) и текст ярче (`--ink`); Загрузить — отдельная сплошная кнопка рядом (`--ink` на `--paper`), явно действие, а не вкладка. Перебирали несколько раскладок — шапка по-разному, нижняя панель как в мобильном приложении, боковая колонка, плавающие кнопки — через временный переключатель прямо на сайте; сначала остановились на боковой колонке, потом решили, что она неудобна, и вернулись в шапку в более лаконичном виде.

## Ленту можно настраивать

Правила, которые бриф оставил на прототип, собраны в одном месте:

- **Порядок ленты обновляется на каждую загрузку страницы** (не хранится между обновлениями): `app/components/Feed.tsx`, seed живёт в памяти вкладки (`lib/persist.ts`, kind `"memory"`).
- **Тёплый и холодный уклон:** иногда лента сама раскладывает кадры так, что кадры одного тона чуть чаще идут подряд — незаметно, кадры не пропадают. Пороги тона и шанс уклона — `lib/feed.ts`, `isWarm`/`isCold`, `TINT_CHANCE`, `TINT_WEIGHT`.
- **Ритм ленты:** `lib/feed.ts`, функция `planFeed`.
  - Главный кадр (три колонки из четырёх, вертикальный две): `bigChance`, `bigGap`.
  - Широкий кадр (две колонки): `wideChance`, `wideGap`.
  - Клетка с подписью плёнки: `noteChance`, `noteGap`.
- **Допустимая пустота под крупным кадром:** `lib/masonry.ts` (`tolerance`, `maxGap`).
- **Появление кадров при прокрутке:** компонент `Reveal` в `app/components/Masonry.tsx` (время, сдвиг, задержка).
- **Колонки и отступы:** `app/components/Masonry.tsx` (4 колонки от 768 px, ниже 2).
- **Цвета и рамка кадра:** `app/globals.css`, переменные в `:root`.

## Стартовый набор кадров

Обычные кадры попадают на сайт через форму загрузки. Отдельно в проекте лежит стартовый набор, которым заполняется
пустая локальная база: две плёнки (72 кадра), Lucky Color 200 (цветная) и Tasma T-42L (чёрно-белая).
Оригиналы лежат в «Загрузках» и в проект не копируются. Для каждого кадра набора сделаны:

- облегчённая копия для ленты, `seed/photos/f` (около 70 КБ);
- крупная копия для просмотра на весь экран, `seed/photos/l`;
- цвет и яркость, посчитанные по картинке, `lib/photos/frames.json`.

Пересобрать набор из оригиналов:

```bash
npm run import
```

Список папок с кадрами задан в начале `scripts/import-photos.mjs` (`SOURCES`).
Данные плёнки (камера, дата, описание) записаны в `lib/catalog.ts`, массив `ROLLS`.
Номер плёнки в `SOURCES` и `id` в `ROLLS` должны совпадать. На сервере набор не используется (`PLENKA_SEED=0`).
