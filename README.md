# [37exp]

Архив плёночных кадров: лента для случайных встреч, папки для целенаправленного просмотра.
Бриф: [brief-mvp.md](brief-mvp.md).

**Это кликабельный прототип с локальной базой.** Кадры настоящие, но «уже загруженные»: файлы лежат прямо в проекте
(`public/photos`). Плёнки, камеры и кадры хранятся в SQLite (`data/plenka.db`), правки папок и удалённые кадры
записываются туда же. Пользователей несколько: каждый, кто вошёл через Яндекс или Google, получает свой архив
и сам решает, кто видит каждую его плёнку (см. «Доступ к плёнкам»). Сама загрузка кадров пока имитация и в базу
ничего не пишет. Цель прототипа: проверить сетку ленты и фон.

## Запуск

```bash
npm install
npm run dev
```

Сайт откроется на http://localhost:3000.

База создаётся сама при первом открытии сайта: файл `data/plenka.db` (не в git) заполняется двумя плёнками и 72 кадрами
из `lib/catalog.ts` и `lib/photos/frames.json`. Начать с чистого листа (правки и удалённые кадры пропадут): остановите
сайт и выполните `npm run db:reset`, база создастся заново. Другое место для файла: переменная `PLENKA_DB_PATH`.

## Доступ к плёнкам

У каждой плёнки есть доступ, его выбирает автор в «Изменить» → «Кто видит эту плёнку»:

| Доступ | Кто видит |
| --- | --- |
| Только я (по умолчанию) | только автор; для остальных плёнки как будто нет (404) |
| Все, у кого есть ссылка | любой, кто пришёл по ссылке `/rolls/<номер>?k=<ключ>` (ключ показан в форме). В списках плёнка не видна, из поиска скрыта |
| Все (видна на моей странице) | любой; плёнка есть на странице автора `/u/<адрес>` |

Правило одно на весь сайт: `lib/access.ts` (`canView`). Смотреть чужие плёнки не нужно входить. Лента и «Папки» показывают
только ваши плёнки. Главная без входа показывает заставку (как пустая лента), «Загрузить» ведёт на вход. Адрес страницы
автора (`/u/<адрес>`) делается из почты при первом входе и показан на `/login`.

**Файлы кадров** лежат на диске сервера в `storage/` (оригиналы, копии для ленты и на весь экран; папка не в git),
а кадры стартового набора в `seed/photos`. Из `public/` они убраны: картинки `/photos/f|l/<id>.jpg` отдаёт
`app/photos` и только тем, кто вправе видеть плёнку (`lib/access.ts`). Ссылка «по ссылке» имеет вид `/s/<ключ>`:
ключ запоминается в cookie зрителя, по нему же открываются картинки. Хранилище — один файл `lib/storage/index.ts`
(его можно переписать под облако). Папку можно вынести: `PLENKA_STORAGE_DIR`.

Загрузка: форма `/upload` отправляет кадры по одному в `app/api/rolls/[id]/frames` (3 параллельно, прогресс и повтор
по каждому). Новая плёнка создаётся с доступом «только я». Лимиты (в `.env.local`): `MAX_FILE_MB` (по умолчанию 40) и
`USER_QUOTA_GB` (по умолчанию 10 на пользователя). Регистрация открытая, поэтому лимит нужно держать.

## Вход через Яндекс или Google

Войти можно на странице `/login` (туда же ведут `/upload` и `/rolls`, пока вы не вошли). Кнопки показываются только для
тех сервисов, ключи которых заданы в `.env.local`; хватит одного. Войти может любой, и у каждого свой архив. Почты в
`OWNER_EMAILS` задают владельца сайта: при первом входе он получает архив, который уже лежит в базе (плёнки из seed).
Впишите туда свою почту. Входите одним сервисом: если почты сервисов разные, второй вход будет считаться отдельным
человеком с пустым архивом.

### Яндекс (без карты)

1. Откройте [oauth.yandex.ru](https://oauth.yandex.ru/) под аккаунтом, которым будете входить, и нажмите «Создать приложение».
2. Тип приложения: для авторизации пользователей (после регистрации его поменять нельзя). Название: `37exp`.
3. Платформа: «Веб-сервисы». Callback URI #1: `http://localhost:3000/api/auth/yandex/callback` (порт должен совпадать
   с тем, на котором запущен сайт).
4. Доступы: адрес электронной почты (`login:email`), имя и фамилия (`login:info`), портрет пользователя (`login:avatar`).
5. Создайте приложение, скопируйте ID и пароль приложения в `.env.local`: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`.

### Google

Нужен проект в [Google Cloud Console](https://console.cloud.google.com/). Карта для этого не требуется: не активируйте
платный пробный период.

1. Настройте экран согласия («Google Auth Platform»): название `37exp`, тип «External», свою почту добавьте в
   «Test users» (пока приложение в режиме «Testing», войти смогут только они).
2. «Clients» → «Create client» → «Web application». В «Authorized redirect URIs» добавьте
   `http://localhost:3000/api/auth/google/callback`. Названия пунктов в консоли Google иногда меняются.
3. Скопируйте ключи в `.env.local`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

### Общее

Скопируйте `.env.example` в `.env.local`, заполните ключи и `OWNER_EMAILS`, перезапустите `npm run dev` (переменные
читаются при старте). `.env.local` в git не попадает. При первом входе владельца за ним закрепляются плёнки и кадры
из базы.

Когда появится домен: добавьте адрес возврата с ним (`https://ваш-домен/api/auth/yandex/callback` и/или
`.../google/callback`) в настройках приложения и пропишите `APP_URL=https://ваш-домен`. Для Google ещё переведите экран
согласия в «In production» (для базового профиля проверка не нужна).

## Что где

| Экран | Адрес | Файл |
| --- | --- | --- |
| Лента | `/` | `app/components/Feed.tsx`, `Masonry.tsx` |
| Папки | `/rolls` (мои) | `app/components/RollsBrowser.tsx` |
| Страница автора | `/u/[handle]` | `app/u/[handle]/page.tsx` |
| Плёнка | `/rolls/[id]` (по доступу) | `app/rolls/[id]/page.tsx`, `app/components/RollDetail.tsx`; правка и удаление кадра: `app/rolls/[id]/actions.ts` |
| Кадр на весь экран | поверх ленты и плёнки | `app/components/Lightbox.tsx` |
| Загрузка | `/upload` (после входа) | `app/components/UploadPrototype.tsx` |
| Вход и выход | `/login` | `app/login/page.tsx`, `app/api/auth/[provider]/` |

Логика без интерфейса лежит в `lib/`:

- `db/`: слой данных на SQLite (better-sqlite3).
  - `index.ts`: единственная точка доступа для страниц и серверных действий (список плёнок, плёнка по id, кадры плёнки,
    кадры для ленты, правка плёнки, удаление кадра). Функции асинхронные и отдают простые объекты, чтобы позже заменить
    SQLite на размещённую базу, переписав только `queries.ts` и `connection.ts`.
  - `queries.ts`: SQL-запросы. `connection.ts`: открытие файла. `schema.ts`: таблицы и миграции (`users`, `cameras`,
    `rolls`, `frames`; у камер и плёнок есть `user_id`). `seed.ts`: первичное заполнение. `user.ts`: пользователь с данными из seed,
    которого забирает владелец при первом входе. Чтение чужого идёт только через `getRollForViewer` и `getPublicProfile`
    (они проверяют `lib/access.ts`), «мои» функции работают с `userId` вошедшего.
  - Удалённый кадр остаётся в базе и на диске с отметкой `deleted_at`, просто нигде не показывается.
- `auth/`: вход и сессии. `session.ts`: сессия в cookie (в ней случайный токен, в базе только его sha256),
  `getViewer()` (кто смотрит) и `requireUser()` (проверка в серверных действиях: правит только своё). `config.ts`: переменные окружения,
  почты владельца сайта `OWNER_EMAILS`. `providers.ts`: Google и Яндекс на библиотеке `arctic`; новый способ входа — ещё один объект в `PROVIDERS`.
- `catalog.ts`: типы, справочник плёнок (его пока нет в базе), сборка названия («Kodak Gold 200 · июль 2025»).
  Массивы `ROLLS`, `CAMERAS`, `FRAMES` в нём — стартовые данные для базы; пока их ещё читают прототип загрузки
  (`UploadPrototype.tsx`) и пустая лента (`WelcomeReel.tsx`).
- `feed.ts`: режимы ленты (вперемешку, по цвету, тёплые, холодные, светлые, тёмные, ч/б) и правила ритма.
- `masonry.ts`: раскладка сетки без обрезки кадров.
- `folder-name.ts`: подсказка по названию папки при загрузке.

## Дизайн

Тёмная тема, чёрный фон. Два шрифта:

- **IBM Plex Sans** — весь текст на сайте: интерфейс, заголовки, названия плёнок. Подключён в `app/layout.tsx`, переменная `--font-plex`.
- **Anton** — только логотип «[37exp]» в шапке (`app/components/SiteHeader.tsx`, класс `font-logo`). В нём нет кириллицы, поэтому для русского текста не используется.

Курсив нигде не используется. Раньше для заголовков и названий плёнок был отдельный шрифт (Cormorant Garamond) — от него отказались в пользу одного шрифта на весь сайт; если это решение нужно будет пересмотреть, история и причины — в `git log`.

Цвета — переменные в `app/globals.css`, `:root`.

Навигация — в правом углу шапки (`app/components/SiteHeader.tsx`): Лента/Папки — переключатель в общей капсуле (`--paper-deep`), активный пункт светлее (`--paper-edge`) и текст ярче (`--ink`); Загрузить — отдельная сплошная кнопка рядом (`--ink` на `--paper`), явно действие, а не вкладка. Перебирали несколько раскладок — шапка по-разному, нижняя панель как в мобильном приложении, боковая колонка, плавающие кнопки — через временный переключатель прямо на сайте; сначала остановились на боковой колонке, потом решили, что она неудобна, и вернулись в шапку в более лаконичном виде.

## Ленту можно настраивать

Правила, которые бриф оставил на прототип, собраны в одном месте:

- **Порядок ленты обновляется на каждую загрузку страницы** (не хранится между обновлениями): `app/components/Feed.tsx`, seed живёт в памяти вкладки (`lib/persist.ts`, kind `"memory"`).
- **Тёплый и холодный уклон:** иногда лента сама раскладывает кадры так, что кадры одного тона чуть чаще идут подряд — незаметно, кадры не пропадают. Пороги тона и шанс уклона — `lib/feed.ts`, `isWarm`/`isCold`, `TINT_CHANCE`, `TINT_WEIGHT`.
- **Ритм ленты:** `lib/feed.ts`, функция `planFeed`.
  - Главный кадр (три колонки из четырёх, вертикальный две): `bigChance`, `bigGap`.
  - Широкий кадр (две колонки): `wideChance`, `wideGap`.
  - Клетка с подписью плёнки: `noteChance`, `noteGap`.
- **Допустимая пустота под крупным кадром:** `lib/masonry.ts` (`tolerance`, `maxGap`).
- **Появление кадров при прокрутке:** компонент `Reveal` в `app/components/Masonry.tsx` (время, сдвиг, задержка).
- **Колонки и отступы:** `app/components/Masonry.tsx` (4 колонки от 768 px, ниже 2).
- **Цвета и рамка кадра:** `app/globals.css`, переменные в `:root`.

## Кадры

Сейчас в прототипе две плёнки (72 кадра): Lucky Color 200 (цветная) и Tasma T-42L (чёрно-белая).
Оригиналы лежат в «Загрузках» и в проект не копируются. Для каждого кадра делаются:

- облегчённая копия для ленты, `public/photos/f` (около 70 КБ);
- крупная копия для просмотра на весь экран, `public/photos/l`;
- цвет и яркость, посчитанные по картинке, `lib/photos/frames.json`.

```bash
npm run import
```

Список папок с кадрами задан в начале `scripts/import-photos.mjs` (`SOURCES`).
Данные плёнки (камера, дата, описание) записаны в `lib/catalog.ts`, массив `ROLLS`.
Номер плёнки в `SOURCES` и `id` в `ROLLS` должны совпадать.
